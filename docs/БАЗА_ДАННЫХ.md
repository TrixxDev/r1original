# База данных R1 Riepas (реконструкция из кода)

> ⚠️ В репозитории почти нет миграций (только 7 файлов — websockets, sessions, slot-locking,
> office_mobile_prefs, site_season, is_visible для workingdays/new_workingdays).
> Основная схема существует только на сервере. Этот документ — реконструкция из
> Eloquent-моделей (`$table`, `$primaryKey`, `$fillable`, `$casts`, отношения), миграций и
> raw-SQL запросов. **Для точной схемы (типы, индексы, все колонки) нужен дамп или доступ
> к phpMyAdmin** — см. раздел «Что требует проверки по реальной БД».

СУБД: MySQL (utf8mb4 / utf8mb4_unicode_ci). Дополнительно используется внешняя **MSSQL**
база для зарплатного модуля (`Api\SalaryController`) и ERP Accrual.

## 2. Ключевые таблицы (детально)

### slots — слоты записи (центральная таблица)
PK `slot_id`. Источник: модель `Slot` + миграция `2026_01_15_000001_add_slot_locking_fields`.

| Колонка | Тип/назначение |
|---|---|
| queue_id | FK → queues |
| date | дата слота |
| iorder | порядковый номер слота в дне |
| status / status2 | статус основного / вторичного клиента (1 = занят) |
| takenby / takenby2 | JSON с данными брони (авто, номер, услуга, телефон, email…) |
| cancel_id | уникальный код отмены |
| comment | комментарий |
| createtime/createuser, createtime2/createuser2 | кто/когда создал (–1 = гость) |
| edittime/edituser (+2) | кто/когда правил |
| is_mobile / is_mobile2 | признак мобильной брони |
| **version** | оптимистичная блокировка (int, default 0) |
| **reserved_until** | datetime окончания мягкой резервации |
| **reserved_by** | session id резервирующего (string 100) |
| **extension_count** | число продлений (tinyint, default 0) |
| car_info_json / car_info_vnr / car_info_fetched_at / car_info_source | снапшот данных авто из CarInfo API |

Индексы: `(date, queue_id, iorder)`, `(reserved_until)`.

### queues — очереди (посты/подъёмники)
PK `queue_id`. Колонки из модели: `office_id` (FK → offices), `opentime`, `closetime`,
`slotSize` (default 2), `secondaryAvailable`, `is_public` (NULL/1 = доступна гостям).
Также шаблоны уведомлений (email/SMS) привязаны к очереди.

### workingdays / new_workingdays — расписание по датам
PK `workingday_id`, FK `queue_id`.
- `workingdays` (старая система): `date`, `weekday`, `opentime`, `closetime`, `slotSize`,
  `secondaryAvailable`, `is_visible` (миграция 2026-05-29), признак `is_half` (половинные слоты).
- `new_workingdays` (новая): `date`, `timeopen`, `timeclose`, `timeStep`, `is_opened`,
  `is_visible` (миграция 2026-06-08).

### office_mobile_prefs (миграция 2026-04-21)
PK `office_id`; `lift_slot_count` (tinyint, default 10), `updated_at`. Автозаполнена для офисов 1 и 2.

### sessions (миграция 2026-02-01)
PK `id` (string); `user_id` (nullable, FK users), `ip_address` (45), `user_agent`,
`payload`, `last_activity` (indexed). Без timestamps.

### users
PK `id`. Из модели: `name`, `surname`, `email` (unique), `email_verified_at`, `phone_number`,
`sms_verification_code`, `password`, `new_password`, `company_name`, `company_vat`,
`company_address`, `company_postcode`, `company_city`, `remember_token`, timestamps.
Роли через Spatie/Permission (таблицы `roles`, `permissions`, `model_has_roles` и т.д. — стандарт пакета).

### audits — журнал действий
PK `id`. `audit_time`, `audit_uid` (FK users), `audit_event`, `audit_ip`, `audit_severity`,
`audit_item`, `audit_subitem`, `audit_facility`, `audit_backtrace`, `audit_classname`,
`audit_instance` (снимок объекта), `audit_url`.

### orders_ — заказы магазина
Модель `Order`, таблица `orders_`. Из кода видны: `edituser` (FK users), `phone_number`,
`phone_country_code`, механизм `delete_at` (истечение неоплаченного заказа — чистится
middleware `checkcart`). **Полный состав колонок (суммы, статусы оплаты, доставка) виден
только в реальной БД.**

### cart / cart_config / shop_mobile_cart_items
- `cart` — корзины (модель `Cart`, PK `cart_id`).
- `cart_config` — key-value настройки сайта: `id`, `name` (напр. `site_season`), `abbr`, `value`.
- `shop_mobile_cart_items` — мобильная корзина: `guest_id`, `tire_id`, `quantity` (int),
  `price` (float), timestamps.

### xml_orders — быстрые заказы (модель Quickorder, PK `order_id`).

## 3. Товарные таблицы (повторяющийся паттерн)

Для каждого вида товара — трёхуровневая иерархия **бренд → протектор/модель → товар** плюс
склад партнёров:

```
{type}_brands (brand_id) ─1:N→ {type}_treads|makes (tread_id/make_id, brand_id)
        ─1:N→ {товары} (tire_id/rim_id/stud_id, make_id) ─1:N→ {type}_stock (stock_id)
```

Типичные колонки **товара** (auto_tires, moto_tires, quadr_tires, big_tires, studs):
- `make_id` — FK на протектор/модель;
- `quantity`, `urs_quantity` (склад Ulbroka), `krs_quantity` (склад Kalnciema iela);
- `price1`, `price2`, `price3` — цены;
- `d1..d4`, `sep`, `sep2` — компоненты размера (напр. 205/55 R16);
- `li`, `si` — индексы нагрузки/скорости;
- `code` — артикул; `comment` (для клиентов), `acomment` (для админов);
- `api_brand_title`, `t_title` — данные из API поставщиков.

Колонки **протектора/модели** (`*_treads`, `*_makes`): `brand_id`, `title`/`t_title`,
`slug`, `comment`; у `auto_treads` — `season` (1 = лето, 2 = зима).

Колонки **бренда** (`*_brands`): `title`/`b_title`, `slug`, `b_comment`.

Колонки **склада** (`*_stock`): `tire_id`/`rim_id`, `article` (артикул партнёра), `quantity`,
`itype` — источник: `'i3' | 'duell' | 'starco' | 'gy' | 'rz' | 'rg'`.

Диски (`rims`, `quadrims`) дополнительно: `skr`, `pcd`, `et`, `dc`, `color`
(сверловка, вылет, центральное отверстие, цвет), `d3` — диаметр, `d1` — ширина.

## 5. Что требует проверки по реальной БД (phpMyAdmin)

Из кода **не видна полная структура** следующих таблиц — известны только PK и часть колонок:

1. **offices** — только PK `office_id`;
2. **services** — PK `service_id`, флаги `f_ac`, `f_moto` упоминаются, остальное неизвестно;
3. **queues** — известна часть колонок, нет типов и шаблонов уведомлений;
4. **orders_** — самая важная: статусы, суммы, позиции, данные оплаты Paysera;
5. **xml_orders**, **cart** — состав колонок;
6. **pages**, **bannerimages**, **promo_codes**, **code** — частично;
7. **filter_cars / filter_models / filter_sizes** — частично;
8. таблицы Spatie (roles, permissions, model_has_roles, model_has_permissions, role_has_permissions) — стандартные, но надо подтвердить;
9. точные типы данных, индексы, charset и наличие FK-ограничений у **всех** таблиц.

### Как снять схему через phpMyAdmin (без передачи доступа)
Вместо выдачи доступа достаточно выполнить во вкладке SQL и прислать результат:

```sql
-- список таблиц с размерами
SELECT table_name, table_rows, engine
FROM information_schema.tables WHERE table_schema = DATABASE();

-- полная схема (повторить для каждой таблицы или выгрузить экспортом «Structure only»)
SHOW CREATE TABLE orders_;
```

Либо: Экспорт → формат SQL → «Только структура» (без данных) — этого достаточно,
персональные данные клиентов не понадобятся.
