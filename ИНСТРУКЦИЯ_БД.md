# 🗄️ Инструкция по настройке БД

## Что нужно добавить в таблицу `slots`

### 3 новых поля:

1. **`version`** (INT, NOT NULL, DEFAULT 0)
   - Версия записи для оптимистичной блокировки
   - Увеличивается при каждом изменении слота

2. **`reserved_until`** (DATETIME, NULL)
   - Время истечения резервации
   - NULL = слот не зарезервирован

3. **`reserved_by`** (VARCHAR(100), NULL)
   - Session ID пользователя, который зарезервировал
   - NULL = слот не зарезервирован

### 2 новых индекса:

1. **`idx_slot_lookup`** (date, queue_id, iorder)
   - Для быстрого поиска слотов

2. **`idx_reserved_until`** (reserved_until)
   - Для быстрой очистки истекших резерваций

## 📊 Что делают новые поля

### Пример работы:

#### 1. Пользователь кликает на слот:
```sql
UPDATE slots 
SET 
    version = version + 1,
    reserved_until = NOW() + INTERVAL 5 MINUTE,
    reserved_by = 'session_abc123'
WHERE slot_id = 1234
  AND version = 0;  -- Проверка версии!
```

#### 2. Другой пользователь пытается кликнуть:
```sql
SELECT * FROM slots 
WHERE slot_id = 1234
  AND (reserved_until IS NULL OR reserved_until < NOW());
-- Вернет 0 строк = слот занят
```

#### 3. Первый пользователь подтверждает запись:
```sql
UPDATE slots 
SET 
    status = 1,
    takenby = '{"name":"John","phone":"123"}',
    version = version + 1,
    reserved_until = NULL,
    reserved_by = NULL
WHERE slot_id = 1234
  AND version = 1  -- Проверка версии!
  AND reserved_by = 'session_abc123';
```

#### 4. Автоматическая очистка истекших резерваций:
```sql
UPDATE slots 
SET 
    reserved_until = NULL,
    reserved_by = NULL
WHERE reserved_until < NOW()
  AND reserved_until IS NOT NULL;
```
