# Предложение новой схемы БД для нового сайта R1 Riepas

Цель: убрать дублирование и legacy, повысить производительность и целостность,
**не потеряв ни одного бизнес-поля** старой БД. Старая схема: 62 таблицы
(см. [БАЗА_ДАННЫХ.md](БАЗА_ДАННЫХ.md)). Новая: **~25 таблиц**.

## Принципы

1. **Всё InnoDB + utf8mb4_unicode_ci** — транзакции и `lockForUpdate()` начинают реально
   работать (сейчас `slots` на MyISAM, и вся блокировка бронирования — фикция на уровне СУБД).
2. **Внешние ключи везде** — целостность перестаёт держаться только на коде.
3. **Один товарный каталог вместо семи.** Сейчас 7 семейств × 3–4 таблицы (~24 таблицы)
   с одинаковой структурой: brand → tread/make → товар → stock. Это один и тот же код,
   скопированный 7 раз — главный источник «говнокода» и в БД, и в контроллерах
   (AutoTireController ≈ MotoTireController ≈ QuadTireController…).
4. **Общие поля — колонками, специфика категории — в JSON** (MySQL 5.7+ умеет JSON
   и генерируемые индексируемые колонки). Это убирает 30 nullable-колонок «на всякий случай».
5. **Деньги — int в центах** везде (сейчас вперемешку double/float/int — double для денег
   даёт ошибки округления).
6. **Слот-сетка отдельно от данных клиента**: сейчас `slots.takenby` — это longtext с JSON,
   по которому нельзя ни искать, ни строить отчёты.

## 1. Каталог товаров: 24 таблицы → 5

```sql
-- Категории как enum в коде: auto, moto, quadr, big, rim, quadrim, stud
CREATE TABLE brands (
  id          INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  category    VARCHAR(10) NOT NULL,           -- auto|moto|quadr|big|rim|quadrim|stud
  title       VARCHAR(255) NOT NULL,
  slug        VARCHAR(100) NOT NULL,
  image       VARCHAR(255) NULL,
  description TEXT NULL,                      -- бывш. b_comment
  sort_order  INT NOT NULL DEFAULT 0,         -- бывш. iorder
  UNIQUE KEY uq_brand (category, slug)
) ENGINE=InnoDB;

CREATE TABLE product_models (                 -- бывш. *_treads / *_makes
  id          INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  brand_id    INT UNSIGNED NOT NULL,
  category    VARCHAR(10) NOT NULL,           -- денормализация для быстрых выборок каталога
  title       VARCHAR(255) NOT NULL,
  slug        VARCHAR(100) NOT NULL,
  season      TINYINT NULL,                   -- 1 лето, 2 зима, NULL — всесезон/неприменимо
  vehicle_type TINYINT NULL,                  -- бывш. t_type: 1 легковые, 2 бусы, 3 4x4
  description TEXT NULL,                      -- бывш. t_comment
  image       VARCHAR(255) NULL,
  sort_order  INT NOT NULL DEFAULT 0,
  UNIQUE KEY uq_model (category, slug),
  KEY idx_brand (brand_id), KEY idx_cat_season (category, season),
  FOREIGN KEY (brand_id) REFERENCES brands(id)
) ENGINE=InnoDB;

CREATE TABLE products (                       -- бывш. auto_tires, moto_tires, quadr_tires,
  id            INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,  -- big_tires, rims, quadrims, studs
  model_id      INT UNSIGNED NOT NULL,
  category      VARCHAR(10) NOT NULL,
  article       VARCHAR(255) NULL,
  -- размер (универсально для шин и дисков; для шипов NULL)
  width         VARCHAR(30) NULL,             -- бывш. d1
  profile       VARCHAR(30) NULL,             -- бывш. d2
  diameter      VARCHAR(30) NULL,             -- бывш. d3
  extra_dim     VARCHAR(30) NULL,             -- бывш. d4 (мото)
  load_index    VARCHAR(11) NULL,             -- li
  speed_index   VARCHAR(10) NULL,             -- si
  -- цены в центах
  price_retail  INT NULL,                     -- бывш. price1
  price_partner INT NULL,                     -- бывш. price2
  price_extra   INT NULL,                     -- бывш. price3
  is_offer      TINYINT(1) NOT NULL DEFAULT 0,        -- offer
  is_price_offer TINYINT(1) NOT NULL DEFAULT 0,       -- priceoffer
  offer_price   VARCHAR(30) NULL, offer_text VARCHAR(30) NULL,
  is_top        TINYINT(1) NOT NULL DEFAULT 0,        -- top / topTire
  is_used       TINYINT(1) NOT NULL DEFAULT 0,        -- used (б/у)
  visible_users TINYINT NOT NULL DEFAULT 1,
  visible_list  TINYINT NOT NULL DEFAULT 1,
  available     TINYINT NOT NULL DEFAULT 1,
  comment       TEXT NULL,                    -- для клиентов
  admin_comment TEXT NULL,                    -- бывш. acomment
  code          VARCHAR(255) NULL,
  attrs         JSON NULL,                    -- специфика категории, см. ниже
  ordered       INT NOT NULL DEFAULT 0,
  reserved      INT NOT NULL DEFAULT 0,
  created_at TIMESTAMP NULL, updated_at TIMESTAMP NULL,
  KEY idx_model (model_id), KEY idx_article (article),
  KEY idx_cat_size (category, width, profile, diameter),
  FOREIGN KEY (model_id) REFERENCES product_models(id)
) ENGINE=InnoDB;
```

**`attrs` JSON по категориям** (всё, что раньше было отдельными колонками):
- auto: `{"eco":"A","wet":"B","noise":"71","type":1}`
- moto/quadr: `{"is_camera":0,"type":"..."}`
- big: `{"implemention":"...","kind":"...","axis":"...","conditions":"...","season":1}`
- rim/quadrim: `{"skr":5,"pcd":"112","et":35,"dc":"66.6","color":"silver"}`
- stud: `{"application":"...","stud_length":8,"stud_count":100}`

Если по какому-то JSON-полю нужен частый поиск (например `pcd`) — добавляется
генерируемая колонка с индексом:
`ALTER TABLE products ADD pcd VARCHAR(20) AS (attrs->>'$.pcd') STORED, ADD KEY idx_pcd (pcd);`

```sql
-- Свои склады: вместо колонок urs_quantity / krs_quantity — строки на офис.
-- Добавление третьего филиала перестаёт требовать ALTER всех товарных таблиц.
CREATE TABLE product_warehouse_stock (
  product_id INT UNSIGNED NOT NULL,
  office_id  INT UNSIGNED NOT NULL,           -- 0 = центральный/виртуальный (бывш. quantity)
  quantity   INT NOT NULL DEFAULT 0,
  PRIMARY KEY (product_id, office_id),
  FOREIGN KEY (product_id) REFERENCES products(id) ON DELETE CASCADE
) ENGINE=InnoDB;

-- Остатки поставщиков: бывш. auto_stock, moto_stock, quadr_stock, bigtire_stock, rim_stock
CREATE TABLE supplier_stock (
  id         INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  product_id INT UNSIGNED NOT NULL,
  supplier   VARCHAR(10) NOT NULL,            -- i3|duell|starco|gy|rz|rg|accrual
  article    VARCHAR(100) NULL,
  quantity   INT NOT NULL DEFAULT 0,
  metadata   JSON NULL,
  created_at TIMESTAMP NULL, updated_at TIMESTAMP NULL,
  KEY idx_product_qty (product_id, quantity),
  KEY idx_article_supplier (article, supplier),
  FOREIGN KEY (product_id) REFERENCES products(id) ON DELETE CASCADE
) ENGINE=InnoDB;
```

Что это даёт коду: вместо 7 контроллеров каталога и 7 контроллеров админки — **один**
`ProductController` с параметром категории; вместо 7 синхронизаций со своим маппингом —
один пайплайн с конфигом на поставщика.

## 2. Бронирование: slots → slots + bookings

```sql
CREATE TABLE slots (                          -- только сетка времени и резервация
  id              INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  queue_id        INT UNSIGNED NOT NULL,
  date            DATE NOT NULL,
  position        INT NOT NULL,               -- бывш. iorder
  status          TINYINT NOT NULL DEFAULT 0, -- 0 свободен, 1 занят, 2 заблокирован
  version         INT NOT NULL DEFAULT 0,
  reserved_until  DATETIME NULL,
  reserved_by     VARCHAR(100) NULL,
  extension_count TINYINT NOT NULL DEFAULT 0,
  comment         TEXT NULL,
  created_by      INT NULL, updated_by INT NULL,
  created_at TIMESTAMP NULL, updated_at TIMESTAMP NULL,
  UNIQUE KEY uq_slot (date, queue_id, position),   -- было только KEY — дубли возможны!
  KEY idx_reserved_until (reserved_until),
  FOREIGN KEY (queue_id) REFERENCES queues(id)
) ENGINE=InnoDB;

CREATE TABLE bookings (                       -- бывш. содержимое slots.takenby (JSON)
  id            INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  slot_id       INT UNSIGNED NOT NULL UNIQUE,
  service_id    INT UNSIGNED NOT NULL,
  cancel_code   VARCHAR(64) NOT NULL UNIQUE,  -- бывш. cancel_id
  car_brand     VARCHAR(100) NOT NULL,
  car_model     VARCHAR(100) NOT NULL,
  license_plate VARCHAR(20) NOT NULL,
  rims_with     TINYINT NULL,                 -- 1 без дисков, 2 с дисками
  phone_number  VARCHAR(20) NOT NULL,
  email         VARCHAR(255) NULL,
  customer_comment TEXT NULL,
  discount      VARCHAR(50) NULL,
  is_mobile     TINYINT(1) NOT NULL DEFAULT 0,
  -- мобильное приложение мастеров (бывш. поля в slots)
  work_status   TINYINT NOT NULL DEFAULT 0,   -- бывш. mobile_status
  ic_status     VARCHAR(20) NULL,
  planned_tasks VARCHAR(255) NULL,
  lift_spot     INT NULL,
  -- снапшот CarInfo
  car_info      JSON NULL,
  car_info_vnr  VARCHAR(16) NULL,
  car_info_fetched_at DATETIME NULL,
  car_info_source VARCHAR(32) NULL,
  created_by INT NULL,                        -- NULL = гость (вместо -1)
  created_at TIMESTAMP NULL, updated_at TIMESTAMP NULL,
  KEY idx_plate (license_plate), KEY idx_phone (phone_number), KEY idx_vnr (car_info_vnr),
  FOREIGN KEY (slot_id) REFERENCES slots(id) ON DELETE CASCADE,
  FOREIGN KEY (service_id) REFERENCES services(id)
) ENGINE=InnoDB;
```

Выигрыш: поиск клиента по номеру/телефону — индексированный запрос вместо `LIKE '%...%'`
по longtext-JSON; статистика по услугам — обычный `GROUP BY`; UNIQUE-ключ на
(date, queue_id, position) делает двойную бронь невозможной даже при багах в коде.

`queues`, `offices`, `services`, `office_mobile_prefs` — оставить как есть (перевести
на InnoDB/utf8mb4, у queues шаблоны уведомлений можно вынести в `notification_templates`,
но это опционально). `workingdays` + `new_workingdays` + `rss_workingdays` → **одна** таблица:

```sql
CREATE TABLE working_days (
  id        INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  queue_id  INT UNSIGNED NOT NULL,
  date      DATE NOT NULL,
  is_draft  TINYINT(1) NOT NULL DEFAULT 0,    -- заменяет new_workingdays
  time_open TIME NULL, time_close TIME NULL,
  time_step TINYINT NOT NULL DEFAULT 15,
  is_opened TINYINT(1) NOT NULL DEFAULT 1,
  is_visible TINYINT(1) NOT NULL DEFAULT 1,
  is_half   TINYINT(1) NOT NULL DEFAULT 0,
  ac_toggle TINYINT(1) NULL, moto_toggle TINYINT(1) NULL,
  UNIQUE KEY uq_day (queue_id, date, is_draft),
  FOREIGN KEY (queue_id) REFERENCES queues(id)
) ENGINE=InnoDB;
```

## 3. Заказы: orders_ → orders + order_items + payments

Главная проблема `orders_`: позиции заказа лежат в `order_details` (text) — нет ни
отчётов по товарам, ни корректного возврата остатков.

```sql
CREATE TABLE orders (
  id            BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  order_number  INT UNSIGNED NOT NULL UNIQUE,
  user_id       BIGINT UNSIGNED NULL,
  session_id    VARCHAR(255) NULL,
  status        TINYINT NOT NULL DEFAULT 0,   -- бывш. order_status
  -- клиент (как было)
  customer_name VARCHAR(255), customer_surname VARCHAR(255),
  email VARCHAR(255), phone_country_code VARCHAR(5), phone_number VARCHAR(50),
  company_reg_nr VARCHAR(20), company_pvn_nr VARCHAR(20),
  company_name VARCHAR(255), company_address TEXT,
  comments TEXT, car_details TEXT, email_notification TINYINT(1) DEFAULT 0,
  -- скидка
  promo_code_id INT UNSIGNED NULL,
  discount_type ENUM('fixed','percentage') NULL, discount_value INT NULL,
  -- суммы в центах
  total_price INT NOT NULL DEFAULT 0,
  delivery_price INT NULL, mounting_price INT NULL,
  -- доставка/монтаж
  delivery_method TINYINT NULL,               -- 1 монтаж, 2 доставка
  delivery_city VARCHAR(255), delivery_address TEXT, door_code VARCHAR(50),
  mounting_office_id INT UNSIGNED NULL,
  admin_info TEXT NULL, edited_by INT NULL,
  expires_at TIMESTAMP NULL,                  -- бывш. delete_at
  created_at TIMESTAMP NULL, updated_at TIMESTAMP NULL,
  KEY idx_status (status), KEY idx_user (user_id), KEY idx_expires (expires_at)
) ENGINE=InnoDB;

CREATE TABLE order_items (                    -- бывш. order_details JSON
  id         BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  order_id   BIGINT UNSIGNED NOT NULL,
  product_id INT UNSIGNED NULL,               -- NULL если товар удалён
  title      VARCHAR(255) NOT NULL,           -- снапшот названия на момент заказа
  article    VARCHAR(255) NULL,
  unit_price INT NOT NULL,                    -- центы, на момент заказа
  quantity   INT NOT NULL,
  FOREIGN KEY (order_id) REFERENCES orders(id) ON DELETE CASCADE,
  FOREIGN KEY (product_id) REFERENCES products(id) ON DELETE SET NULL
) ENGINE=InnoDB;

CREATE TABLE payments (                       -- бывш. paysera_* поля + payment_status
  id             BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  order_id       BIGINT UNSIGNED NOT NULL,
  method         TINYINT NOT NULL,            -- 1 при получении, 2 счёт, 3 онлайн
  status         VARCHAR(20) NOT NULL DEFAULT 'pending',
  amount         INT NOT NULL,
  provider       VARCHAR(20) NULL,            -- 'paysera'
  transaction_id VARCHAR(255) NULL,
  callback_data  JSON NULL,
  processed_at   TIMESTAMP NULL,              -- идемпотентность callback'ов
  created_at TIMESTAMP NULL, updated_at TIMESTAMP NULL,
  UNIQUE KEY uq_provider_tx (provider, transaction_id),
  FOREIGN KEY (order_id) REFERENCES orders(id)
) ENGINE=InnoDB;
```

`carts` (user_id/session_id + JSON cart_data) — оставить одну, `cart` (пакетную) и
`shop_mobile_cart_items` влить в неё. `promo_codes` — как есть, плюс UNIQUE на `code`.
`xml_orders` — оставить как есть (изолированный поток быстрых заказов) или влить
в orders с флагом `source='quick'`.

## 6. План перехода

1. Новая схема в отдельной БД, полностью через **миграции Laravel** (старая БД жила без них —
   это и привело к дрейфу кода и схемы).
2. Скрипт переноса данных (artisan-команда): товары 7 семейств → products,
   разбор `slots.takenby` и `orders_.order_details` JSON → bookings / order_items.
   Прогонять можно многократно (idempotent), сверять счётчики строк.
3. Период двойной работы не нужен: перенос делается за минуты, переключение —
   сменой `.env` у нового сайта.
4. Старую БД сохранить как архив read-only (orders legacy, rims_old и т.п. не переносить,
   но и не удалять до закрытия сезона).

## Что это даёт по производительности

- UNIQUE-ключи вместо «надежды на код»: дубль слота или повторный Paysera-callback
  невозможны на уровне СУБД.
- InnoDB: рабочие транзакции/блокировки, отсутствие table-lock'ов MyISAM при записи
  (сейчас любой UPDATE в slots блокирует всю таблицу).
- Поиск записей по номеру машины/телефону — по индексу, а не LIKE по JSON-тексту.
- Каталог: один набор индексов (category, width, profile, diameter) вместо случайных
  индексов в 7 таблицах.
- Меньше кода: 1 контроллер каталога вместо 7, 1 импорт-пайплайн вместо 7.
