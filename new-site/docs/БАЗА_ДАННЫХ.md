# База данных R1 Riepas (по реальной схеме)

Источник: structure-only дамп phpMyAdmin от 10.06.2026, БД **`r1`**,
сервер **MySQL 5.7.42** (Ubuntu 18.04), PHP 7.4.33. Всего **62 таблицы**.
Связанные документы: [БИЗНЕС_ЛОГИКА.md](БИЗНЕС_ЛОГИКА.md), [КАРТА_ФУНКЦИОНАЛА.md](КАРТА_ФУНКЦИОНАЛА.md).

## Общие характеристики

- **Движки смешанные**: часть таблиц InnoDB, часть **MyISAM** (slots, queues, offices,
  auto_tires, orders (legacy), cart_config и др.). См. раздел «Риски».
- **Кодировки смешанные**: utf8, utf8mb4_unicode_ci, у `xml_orders` — utf8_latvian_ci.
- **Внешних ключей на уровне БД нет**, кроме трёх FK в таблицах Spatie
  (model_has_permissions, model_has_roles, role_has_permissions → CASCADE).
  Все остальные связи — только на уровне приложения (Eloquent).
- Все PK — auto_increment, кроме `cart` (составной PK `identifier+instance`),
  `sessions` (varchar id), `office_mobile_prefs` (office_id), `password_resets` (без PK).

## 1. Система записи (pieraksts)

### slots (MyISAM, utf8) — центральная таблица
PK `slot_id`. Индексы: `queue_id`, `date`, `iorder`, составной `idx_slot_lookup (date, queue_id, iorder)`,
`idx_reserved_until`, `car_info_vnr_idx`, `cancel_id`.

| Колонка | Тип | Назначение |
|---|---|---|
| slot_id | int AI | PK |
| version | int NOT NULL default 0 | оптимистичная блокировка |
| reserved_until | datetime NULL | конец мягкой резервации |
| reserved_by | varchar(100) NULL | session id резервирующего |
| extension_count | tinyint default 0 | число продлений (макс 2) |
| queue_id | int | очередь |
| date | date | дата |
| iorder | int | позиция слота в дне |
| newIorder | int NULL | позиция при переносе (drag&drop) |
| status | int | 1 = занят |
| ic_status | varchar(20) | статус техконтроля (mobile API) |
| ic_planned_tasks | varchar(20) | запланированные работы (mobile API) |
| mobile_status | int default 0 | статус работы в мобильном приложении |
| lift_spot | int NULL | номер подъёмника |
| takenby | longtext | JSON данных брони (авто, номер, услуга, контакты) |
| cancel_id | varchar(191) | код отмены (есть индекс) |
| car_info_json | **json** | снапшот CarInfo API |
| car_info_vnr | varchar(16) | нормализованный VIN/номер |
| car_info_fetched_at | datetime | когда получены данные |
| car_info_source | varchar(32) | источник данных |
| comment | text | комментарий админа |
| appo_edittime / appo_edituser | varchar(40) / int | правка записи (appointment) |
| createtime / createuser | varchar(40) / int default -1 | создание (-1 = гость) |
| edittime / edituser | varchar(40) / int default -1 | редактирование |
| is_mobile | int default 0 | бронь из мобильной версии |

> Примечание: полей `status2 / takenby2 / *2` (вторичный клиент) в реальной схеме **нет** —
> они остались только в старом коде. `createtime` — varchar, не datetime.

### queues (MyISAM)
PK `queue_id`; индексы `office_id`, `is_visible`, `iorder`.
`title`, `is_visible`, `iorder` (порядок отображения), `timeopen`/`timeclose` (varchar 10),
`wtimeopen`/`wtimeclose` (часы выходных), `is_public` (tinyint default 1 — доступна гостям),
и **шаблоны уведомлений**: `notificationEmail`, `notificationCancelEmail`, `notificationSubject`,
`notificationSMS`, `notificationScheduleSMS`, `notificationScheduleCancelSMS`.

### offices (MyISAM)
PK `office_id`: `title` (varchar 100), `shipping` (varchar 50), `queue_count`.

### services (MyISAM)
PK `service_id`: `title`, `pdf_title`, `f_save` (хранение шин), `f_ac` (легковые),
`f_moto` (мото) — флаги допуска к типам слотов, `enabled`.

### workingdays и new_workingdays — идентичная структура
PK `workingday_id` (у workingdays индекс `date`):
`queue_id`, `office_id`, `date`, `weekday`, `timeopen`/`timeclose` (time),
`ac_toggle`, `moto_toggle`, `is_half` (половинные слоты AC/MOTO), `timeStep` (default **15** минут),
`is_opened`. workingdays — InnoDB (рабочая), new_workingdays — InnoDB (черновик для редактирования).

> ⚠️ Колонки `is_visible` из миграций репозитория (2026-05-29 и 2026-06-08) в дампе
> **отсутствуют** — эти миграции на сервере ещё не применены (как и
> `websockets_statistics_entries`).

### rss_workingdays (MyISAM, legacy)
Старая структура расписания: `queue_id`, `secondaryAvailable` (default 0), `slotSize` (default 2),
`date`, `weekday`, `opentime`/`closetime`, `is_visible` (default 1). Соответствует старой
модели `Workingday` из кода.

### office_mobile_prefs (InnoDB)
PK `office_id`: `lift_slot_count` (tinyint unsigned, default 10), `updated_at` (ON UPDATE CURRENT_TIMESTAMP).

## 2. Заказы и корзина

### orders_ (InnoDB, utf8mb4) — актуальные заказы магазина
PK `id` (bigint AI), UNIQUE `order_number`.

| Группа | Колонки |
|---|---|
| Идентификация | order_number (unique), user_id, session_id |
| Клиент | customer_name, customer_surname, email, phone_country_code, phone_number |
| Компания | company_reg_nr (11), company_pvn_nr (13), company_name, company_address |
| Содержимое | order_details (text/JSON), car_details, comments, email_notification enum('0','1') |
| Скидка | promo_code, discount_type enum('fixed','percentage'), discount_value |
| Суммы | total_price (int — в центах), delivery_price, mounting_price |
| Доставка | delivery_method enum('1','2') — 1 = монтаж, 2 = доставка; delivery_city, delivery_address, door_code |
| Монтаж | mounting_office enum('1','2') — 1 = Ulbroka, 2 = Kalnciema |
| Оплата | payment_method enum('1','2','3') — 1 = при получении, 2 = по счёту, 3 = онлайн; payment_status (varchar 20), paysera_transaction_id, paysera_callback_data |
| Статус/служебные | order_status (int), admin_info, edituser, created_at, updated_at, **delete_at** (TTL неоплаченного заказа — чистит middleware checkcart) |

### orders (MyISAM, legacy)
Старая таблица заказов: userId, userIp, status, used_promo, price, delivery_price,
fit_price, info, admin_info, payment, edituser.

### cart (InnoDB) — формат пакета shoppingcart
PK составной (`identifier`,`instance`); `content` (longtext, сериализованная корзина).

### carts (InnoDB) — собственная реализация
PK id; `user_id`, `session_id`, `cart_data` (text), `total_sum` (int).

### shop_mobile_cart_items (InnoDB)
PK id; `guest_id` (char 36, UUID), `tire_id`, `quantity`, `price` decimal(10,2);
UNIQUE (`guest_id`,`tire_id`).

### xml_orders (MyISAM, utf8_latvian_ci) — быстрые заказы
PK `order_id`: `office`, `item_article`, `quantity`, `price_per_one`, `total_price`,
`fitting`, `fitting_price`, `safe` (хранение), `safe_price`, `phone`, `phone_number`,
`admin_id`, `sms_sended`, timestamps.

### promo_codes (InnoDB)
PK `promo_id`: `name`, `code`, `end_date`, `status` enum('1','2') — 1 = %, 2 = фикс. сумма;
`value`, `active` enum('0','1'), `can_use` (NULL = безлимит), `used` (счётчик), timestamps.

### cart_config (MyISAM) — key-value настройки
PK id: `name`, `abbr`, `value` (здесь же `site_season`: 1 = лето, 2 = зима).

## 3. Товарные таблицы

Иерархия для каждого типа: **бренд → протектор/модель → товар → сток партнёров**.
FK в БД не объявлены, связи через `brand_id` / `make_id` / `tire_id` (`rim_id`).

### Автошины
- **auto_brands**: brand_id, title, slug (idx), b_comment.
- **auto_treads**: tread_id, season (1 — vasara/лето, 2 — ziema/зима), brand_id, t_title,
  slug (idx), t_comment, t_type (1 — легковые, 2 — бусы, 3 — 4x4).
- **auto_tires** (индексы make_id, article, quantity): tire_id, make_id, d1/d2 (double),
  d3 (varchar 6), used, price1/price2 (double), offer, priceoffer, offerPrice/offerText,
  comment/acomment, li/si, type, visible_users/visible_list (default 1), available (default 1),
  code, **eco/wet/noise** (EU-этикетка), article, quantity (default −1), `urs_quantity`,
  `krs_quantity` (склады Ulbroka/Kalnciema), ordered, reserved, top, topTire, updated_at.
- **auto_stock** (индексы (article,itype), tire_id, (tire_id,quantity)): stock_id, tire_id,
  article, quantity (double), itype ('i3','duell','starco','gy','rz','rg'), metadata (text), timestamps.

### Мотошины
moto_brands / moto_treads (+iorder) / **moto_tires** (d1–d4 varchar, sep, is_camera — камерная,
остальное как у авто; индексы по d1–d4, article) / moto_stock (как auto_stock).

### Квадрошины
quadr_brands (b_title) / quadr_treads / **quadr_tires** (d1, sep, d2, sep2, d3 double, is_camera,
прочее аналогично; индексы d1/d2/d3/article) / quadr_stock.

### Промышленные шины (big)
bigtire_brands (+image) / bigtire_treads (+image, season) / **big_tires**
(d1 varchar, sep, d2/d3 float, type, li/si, price1–3, **implemention, kind, axis, conditions** —
агро-специфика, прочее стандартно) / bigtire_stock (+type).

### Диски авто
- **rim_brands**: brand_id, title, slug, iorder, image.
- **rim_makes**: make_id, season, brand_id, title, slug, t_comment, type, iorder, node_id.
- **rims** (индексы make_id, d1, d3, skr, et, pcd, article): rim_id, make_id, d1 (ширина, float),
  d3 (диаметр, smallint), dc (центр. отверстие), used, price1–3, skr (кол-во болтов),
  pcd (разболтовка), et (вылет), color, article, количества/видимость стандартно.
- **rim_stock**: stock_id, rim_id, article, quantity, itype, metadata, timestamps;
  индекс (rim_id, quantity).
- **rims_steel** (legacy): штампованные диски — model, cars, d3x/d1x/sac/etx, price1/2, available*.
- **rims_old** (legacy): size, price, comment, cars, image.

### Диски квадроциклов
quadrim_brands (b_title, iorder, image) / quadrim_makes (season, type, iorder, node_id) /
**quadrims** (d1 varchar, d3 smallint, skr/pcd/et/color, price1–3, количества стандартно;
индексы d1, d3, skr, et, pcd, article).

### Шипы
studs_brands (b_title) / studs_treads (t_title) / **studs**: stud_id, make_id,
application (применение), stud_length, stud_count, price1/price2, видимость/количества стандартно.

### Подбор по автомобилю
- **filter_cars**: car_id, title (марка).
- **filter_models**: model_id, carId, title (модель).
- **filter_sizes**: size_id, modelId, r (радиус), j (ширина), jMin, et, skr, pcd, d —
  допустимые параметры дисков для модели.

## 4. Пользователи и доступ

### users (InnoDB, utf8mb4)
PK id (bigint), UNIQUE email: `name`, `surname`, **`username`** (varchar 50), `email`,
`email_verified_at`, `phone_number` (15), `password`, **`gender`** (varchar 4),
`remember_token`, **`lastActivityTime`** (datetime, default now), **`enabled`** (default 1 —
вкл/выкл аккаунта админом), timestamps.

> ⚠️ Расхождение с кодом: в `$fillable` модели User есть `company_name`, `company_vat`,
> `company_address`, `company_postcode`, `company_city`, `sms_verification_code`,
> `new_password` — **этих колонок в таблице нет**. Запись этих полей упадёт с SQL-ошибкой.

### sessions (InnoDB)
PK id (varchar): user_id (idx), ip_address (45), user_agent, payload, last_activity (idx).

### Spatie/Permission (InnoDB, единственные FK в БД)
roles, permissions (UNIQUE name+guard_name), model_has_roles, model_has_permissions,
role_has_permissions — стандартная схема пакета, FK с ON DELETE CASCADE.

### password_resets
email (idx), token, created_at. Без PK.

## 5. Служебные таблицы

- **audits** (InnoDB): id, audit_time, audit_uid, audit_event, audit_ip (15), audit_severity,
  audit_item, audit_facility, audit_subitem, audit_backtrace, audit_classname,
  audit_instance, audit_url. Индексов кроме PK нет (при росте журнала выборки будут медленными).
- **sync_times** (InnoDB): sync_id, name (varchar 50), updated_at — время последней
  синхронизации каждого поставщика (для страницы /admin/settings/syncs).
- **pages** (MyISAM): id, title, route — только заголовок и маршрут;
  **колонки `content` нет** (контент страниц живёт в blade-шаблонах).
- **bannerimages** (InnoDB): id, name, url, enabled.
- **code** (InnoDB): code_id, name (50), explanation — расшифровки маркировки шин.
- **failed_jobs**, **migrations** — стандартные Laravel.

## 7. Риски и расхождения кода с БД (важно)

1. **`slots` — MyISAM.** MyISAM не поддерживает ни транзакции, ни строчные блокировки.
   Вся защита бронирования (`DB::transaction()` + `lockForUpdate()` в
   `SlotReservationService` и `RecordController::fillSlot`) на этой таблице **фактически
   не работает на уровне СУБД** — спасает только оптимистичное версионирование (`version`)
   и проверка `reserved_by`. Перевод `slots` (а также `queues`, `offices`, `services`,
   `workingdays`-legacy) на InnoDB закроет окно для race condition по-настоящему.
2. **Миграции репозитория не применены на сервере**: нет колонок `is_visible` в
   `workingdays`/`new_workingdays` (миграции 2026-05-29, 2026-06-08) и нет таблицы
   `websockets_statistics_entries`. Код, который их использует, упадёт.
3. **Модель User не соответствует таблице** (company_*, sms_verification_code,
   new_password отсутствуют в БД).
4. **Двойные/унаследованные таблицы**: orders vs orders_, cart vs carts,
   workingdays vs new_workingdays vs rss_workingdays, rims vs rims_steel vs rims_old —
   актуальны соответственно orders_, carts(+cart для пакета), workingdays/new_workingdays, rims.
5. **Нет FK и смешанные кодировки** — целостность держится только на коде;
   utf8 (3-байтовая) в товарных таблицах не примет emoji/редкие символы.
6. **audits без индексов** по audit_time/audit_uid — журнал со временем замедлит админку.
