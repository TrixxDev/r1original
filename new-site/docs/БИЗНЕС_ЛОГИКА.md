# Бизнес-логика R1 Riepas

Документ описывает бизнес-логику проекта, восстановленную из исходного кода (Laravel).
Связанные документы: [КАРТА_ФУНКЦИОНАЛА.md](КАРТА_ФУНКЦИОНАЛА.md), [БАЗА_ДАННЫХ.md](БАЗА_ДАННЫХ.md).

## Обзор системы

R1 Riepas — платформа шиномонтажного сервиса (Латвия), объединяющая два основных направления:

1. **Интернет-магазин** — продажа шин (авто/мото/квадро/промышленные), дисков, шипов; корзина, заказы, оплата через Paysera, синхронизация остатков с поставщиками.
2. **Система записи на услуги (pieraksts)** — онлайн-бронирование слотов времени на шиномонтаж в филиалах, с защитой от двойного бронирования.

Два филиала (offices): **office_id=1 — Ulbroka (URS)**, **office_id=2 — Kalnciema iela, Rīga (KRS)**.

## 1. Бронирование слота (ядро системы записи)

### Константы

| Параметр | Значение | Где |
|---|---|---|
| Таймаут резервации `RESERVATION_TIMEOUT` | 5 минут | `app/Services/SlotReservationService.php` |
| Максимум продлений `MAX_EXTENSIONS` | 2 (итого до 15 минут) | там же |
| Шаг слота (timeStep) | обычно 15 минут | `SlotService`, `RecordController` |
| Горизонт рабочих дней | 14 дней | `WorkingDaysProvisioner` |

### Полный поток бронирования

**Шаг 1. Клик по слоту (frontend, `public/js/simple-slot-lock.js`).**
Пользователь кликает на свободный слот в календаре → JS перехватывает клик и шлёт
`POST /pieraksts/reserve-slot` с `queue_id`, `date`, `iorder`.

**Шаг 2. Мягкая резервация (`SlotReservationService::reserveSlot`).**
В транзакции БД:
1. Очищаются все истёкшие резервации (`reserved_until < now`).
2. Слот блокируется через `lockForUpdate()`.
3. Проверки:
   - слот уже забронирован (`status == 1 && takenby`) → ошибка «Laiks jau ir aizņemts»;
   - зарезервирован другой сессией → ошибка с временем истечения;
   - зарезервирован той же сессией и резервация валидна → успех (счётчик продлений не сбрасывается).
4. При успешной резервации: `reserved_until = now + 5 мин`, `reserved_by = session_id`
   (именно ID сессии, не user_id), `extension_count = 0`, `version++`.

**Шаг 3. Таймер на фронте.**
Каждую секунду JS сверяет `expiresAt`. За 60 секунд до истечения — модальное окно
«сессия истекает» с кнопками «Iziet» / «Turpināt» (на мобильных — вибрация).
По нулю — «резервация истекла», страница перезагружается.

**Шаг 4. Продление (`SlotReservationService::extendReservation`).**
Допускается только той же сессией и только пока резервация валидна.
Если `extension_count >= 2` — резервация очищается, пустой слот
(`status=0 && !takenby && !comment`) удаляется, возвращается ошибка
«Pagarināšanas iespējas ir izmantotas», клиент закрывает форму и перезагружает страницу.
Иначе: `reserved_until = now + 5 мин`, `extension_count++`, `version++`.

**Шаг 5. Заполнение формы (`RecordController::fillSlot`).**
Обязательные поля: `car_brand`, `car_model`, `lic_plate` (госномер), `service`,
`phone_number` (numeric); для услуги с `service_id=1` — `rimsWith` (1 — без дисков, 2 — с дисками).
Опционально: `email`, `user_comment`, а также снапшот данных авто из API CarInfo
(`car_info_json` до 50 000 байт, `car_info_vnr`, `car_info_fetched_at`, `car_info_source`).

**Шаг 6. Жёсткое бронирование (транзакция в `fillSlot`).**
1. `lockForUpdate()` на слот.
2. Тройная проверка: слот не занят, не зарезервирован чужой сессией, нет конфликта comment/takenby.
3. Обновление: `status = 1`, `takenby = JSON с данными формы`,
   `cancel_id = random_hash + time_suffix` (уникальный код для отмены),
   `createtime = now`, `createuser = auth()->id() или -1`, `version++`.
4. Поля резервации очищаются (`reserved_until/reserved_by = null`, `extension_count = 0`).

**Шаг 7. Уведомления после бронирования (`FillSlotBookingNotifications`, асинхронно — afterResponse):**
1. **Email** (если указан): тема и текст из шаблона очереди, BCC `karlis@r1riepas.lv` (`App\Mail\CartMail`, view `emails.cartemail`).
2. **SMS** через `SmsSender` — текст из шаблона очереди (время, авто, услуга).
3. **WhatsApp (TextMeBot)** — только если запись на сегодня (timezone Europe/Riga).
   Текст: `Jauns pieraksts - TIME | BRAND MODEL | PLATE | SERVICE | [RIMS] | [COMMENT] | [DISCOUNT]`.
   Группы: URS (office 1) и KRS (office 2), отдельные WhatsApp-группы (JID `...@g.us`).
4. **WhatsApp (Parallel API)** — альтернативный провайдер, активен при
   `WHATSAPP_PARALLEL_ENABLED=true` + `WHATSAPP_PARALLEL_API_KEY`; JSON API с заголовком `X-API-Key`.
5. **WebSocket-уведомление** (`AppointmentNotifyService`) — POST на `APPOINTMENT_NOTIFY_URL`
   с `date`, `columnId` (queue_id), `slotIndex` (iorder) для realtime-обновления админ-панели.

### Отмена записи

`GET /pieraksts/cancel={cancel_id}` — отмена по уникальному коду из письма/SMS.

### Защита от race conditions (двухуровневая)

- **Soft lock**: `reserved_until` + `reserved_by` (session id); истёкшие резервации чистит
  cron каждую минуту и сам сервис при каждой попытке резервации.
- **Hard lock**: `DB::transaction()` + `lockForUpdate()` + оптимистичное версионирование
  (поле `version`, инкремент при каждом изменении слота).
- Индексы: `(date, queue_id, iorder)` для поиска слота, `reserved_until` для очистки.

### Half-slots (половинные слоты)

Если у рабочего дня `is_half == 1`, слоты чередуются между типами AC / MOTO / blocked:
- нечётный `iorder` (1,3,5…) → blocked, moto или legacy_free;
- чётный `iorder` (2,4,6…) → ac или legacy_free.

При бронировании проверяются флаги услуги: `service->f_ac == 1` разрешает AC-слот,
`service->f_moto == 1` — MOTO-слот, иначе ошибка о несоответствии услуги.

### Публичность очередей

Неавторизованный клиент может бронировать только очереди с `is_public == 1` (или NULL —
по умолчанию публичная). Авторизованный администратор — любые.

## 2. Интернет-магазин и оплата

### Корзина и оформление (`ShopController`)

- Добавление в корзину (в т.ч. AJAX и «парный комплект» dual-kit — 8 шин), изменение количества, удаление, очистка.
- Проверка доступности **доставки** (`checkShipping`) и **монтажа** (`checkFitting`).
- Ввод данных клиента (`/credentials`), оформление (`/checkout`) с интеграцией Paysera.
- Страницы успеха `/shop/success/{id}` и `/shop/done/{order_number}`, печать заказа.
- Промокоды: проверка через `PromoCodeController@checkPromo`.
- Middleware `checkcart` удаляет истёкшие заказы (`delete_at < now`).

### Оплата Paysera

Конфигурация в `config/payment.php`: project_id `209872`, валюта EUR, страна LV,
тестовый режим выключен (`PAYSERA_TEST_MODE`). Подпись запроса — секрет `sign_password`
(хранится в конфиге/окружении).

Поток:
1. `WebToPay::buildRequest()` формирует параметры: `projectid`, `orderid`, `amount` (в центах),
   `currency`, `accepturl`, `cancelurl`, `callbackurl`, `paytext`, `lang`.
2. Данные кодируются base64, подпись `MD5(data + sign_password)`.
3. Редирект на `https://bank.paysera.com/pay/?data=...&sign=...`
   (в тестовом режиме — sandbox).
4. **Callback** (`PayseraCallbackController@callback`, маршрут `ANY /callback`):
   `WebToPay::validateAndParseData()` проверяет подпись (SS1/SS2) и projectid.
   Статусы: `1` — успех, `3` — неудача. При корректной обработке выводится `OK`.
   Callback может приходить повторно — требуется идемпотентность по `orderid`.

### Быстрые заказы и партнёры

- **Quick-order** (`/quick-order`, auth): заказ по артикулам с отправкой в ERP Accrual
  (`HomeController@accrualOrder`), SMS-подтверждение.
- **Accrual-партнёры**: поиск/добавление (`AccrualPartnerController`).
- **Счета с предоплатой** (`PrepaymentInvoiceController`): выдача счетов по номеру/году/ссылке заказа, проверка статуса.

### Синхронизация остатков с поставщиками (`SyncController`)

Источники: **Accrual** (ERP), **I3** (авто/мото/квадро/промышленные/агро шины, литые диски),
**Goodyear**, **RZ Auto**, **Riepu Garāža** (XML), **Duell** (мото/квадро), **Starco**.
Остатки партнёров хранятся в таблицах `*_stock` с полем `itype`
('i3', 'duell', 'starco', 'gy', 'rz', 'rg'). Помимо них у товаров есть собственные остатки
магазина: `urs_quantity` (Ulbroka) и `krs_quantity` (Kalnciema iela).

### Маркетинг

- Фиды: Google Merchant Center (`/marketing/feed/google.xml`), Salidzini.lv (`/xml/salidzini`), Kurpirkt.lv (`/xml/kurpirkt`).
- Акции: `TopTireController` (флаг «Top» у товара).
- Трекинг конверсий: `GoogleAdsConversionService`, `MetaConversionsApiService`, `PurchaseTrackingService`.

## 3. Сезонность

`SiteSeasonService` хранит текущий сезон сайта в таблице `cart_config` (ключ `site_season`):
**1 = лето, 2 = зима** (с кешированием). Влияет на:
- каталоги (`/vasaras-riepas` vs `/ziemas-riepas`, сезон у `auto_treads.season`);
- часы работы и набор услуг;
- переключается админом: `POST /admin/changeSeason`.

---

## 4. Рабочие дни и очереди

- **queues** — очереди (подъёмники/посты) филиала: `office_id`, `opentime`, `closetime`,
  `slotSize` (по умолчанию 2), `secondaryAvailable`, `is_public`.
- **workingdays** (старая система) и **new_workingdays** (новая/черновая) — расписание по датам:
  открытие/закрытие, шаг времени, `is_opened` (например, 0 по воскресеньям), `is_visible`
  (скрытие от клиентов; поле добавлено миграциями 2026-05/06).
- **WorkingDaysProvisioner** — генерация рабочих дней на 14 дней вперёд для всех очередей
  (выходные — отдельные часы `wtimeopen`/`wtimeclose`, воскресенье — закрыто).
  Запуск по расписанию в 00:05 сейчас **отключён** в `app/Console/Kernel.php`.
- Редактирование времён через `/pieraksts/darba-laiki` с механикой
  «черновик → сохранить/отменить» (`changeTimes` / `saveTimeChanges` / `cancelTimeChanges`).

## 5. Мобильное приложение мастеров (API)

`Api\MobileSlotsController` + `Api\OfficeMobilePrefsController`, защита Bearer-токеном
(`MOBILE_API_TOKEN`, middleware `mobile.token`):
- статусы подъёмников (lift-spots), список записей на дату;
- обновление статуса записи, статуса техконтроля (IC), запланированных работ, данных клиента;
- настройки филиала: `office_mobile_prefs.lift_slot_count` (по умолчанию 10) — число
  отображаемых подъёмников на офис.

Отдельно — **API зарплат** (`Api\SalaryController`, auth:api) с подключением к внешней
MSSQL-базе: поиск сотрудника, зарплаты, больничные, статусы выплат, полный отчёт.

## 7. События и broadcasting (WebSocket)

Канал `slots`, события:
- `SlotReserved` (`slot.reserved`) — мягкая блокировка: queue_id, date, iorder, reserved_by, reserved_until, session_id;
- `SlotBooked` (`slot.booked`) — слот забронирован;
- `SlotReleased` (`slot.released`) — резервация снята, причина: `cancelled` / `expired` / `booked`;
- `CartUpdated` — изменение корзины.

Каналы админки: AdminNewSlotChannel, EditSlotChannel, DeleteSlotChannel, ToggleQueueChannel,
UpdateStockChannel, MoveSlotChannel, ChangeQueueChannel, NewSlotChannel.
Админ-панель слушает канал и обновляет таблицу слотов в реальном времени.

## 8. Аудит и логирование

- **Audit trail**: все значимые операции пишутся в таблицу `audits`
  (`Audit::audit(severity, facility, item, uid, событие, контекст)`) — время, пользователь, IP,
  событие, класс/состояние объекта, URL, backtrace. Просмотр: `/admin/audits`.
- **WhatsappErrorLogger** — ошибки WhatsApp-отправки в отдельный лог.
- **RequestTimingDebug / SessionTimingDebug** — middleware замера времени запросов/сессий.

---

## 9. Роли и доступ

- RBAC на **Spatie/Permission**: роль `administrators` обязательна для `/admin/*`
  (middleware `admin`, при отсутствии роли — 404). Роли и разрешения управляются в `Admin\RoleController`.
- Регистрация публичных пользователей **отключена** (`register=false`), вход/сброс пароля доступны.
- Личный кабинет требует `auth + verified` (подтверждение email).
- SMS-верификация: notification `SendSmsVerificationCode` («Jusu verifikacijas kods ir {code}»).
