## Что происходит при отправке формы

```
ПОЛЬЗОВАТЕЛЬ 1 заполняет форму и нажимает "Подтвердить"
    ↓
JavaScript отправляет форму + slot_id + version
    ↓
RecordController::fillSlot()
    ↓
DB::beginTransaction()
    ├─ lockForUpdate() - блокирует строку в БД
    ├─ Проверка version (защита от race condition)
    ├─ Проверка что слот еще свободен
    ├─ Сохранение записи:
    │   ├─ status = 1
    │   ├─ takenby = JSON с данными
    │   ├─ version++
    │   ├─ reserved_until = NULL
    │   └─ reserved_by = NULL
    └─ DB::commit()
    ↓
Отправка SMS, Email, WhatsApp
    ↓
Ответ: { success: true, message: "Запись создана!" }
    ↓
JavaScript:
    ├─ Закрыть форму
    ├─ Показать успех
    └─ Перезагрузить страницу через 2 сек
```

## Защита от race conditions

### Проблема:
```
Пользователь 1: Читает слот (status=0) ──┐
                                          ├─→ Оба видят свободный слот
Пользователь 2: Читает слот (status=0) ──┘
                                          
Пользователь 1: Сохраняет запись ────────┐
                                          ├─→ КОНФЛИКТ!
Пользователь 2: Сохраняет запись ────────┘
```

### Решение 1: lockForUpdate()
```php
DB::beginTransaction();
$slot = Slot::where('slot_id', $id)->lockForUpdate()->first();
// Строка заблокирована! Другие запросы ждут.
$slot->status = 1;
$slot->save();
DB::commit();
// Строка разблокирована
```

### Решение 2: Версионирование
```php
// Пользователь 1 получил version = 5
// Пользователь 2 получил version = 5

// Пользователь 1 сохраняет:
if ($slot->version == 5) {  // ✅ OK
    $slot->version = 6;
    $slot->save();
}

// Пользователь 2 пытается сохранить:
if ($slot->version == 5) {  // ❌ FAIL! Уже 6
    return "Слот изменен!";
}
```

## Структура данных

### Таблица slots:

```
slot_id | queue_id | date       | iorder | status | version | reserved_until      | reserved_by
--------|----------|------------|--------|--------|---------|---------------------|-------------
123     | 1        | 2026-01-15 | 10     | 0      | 5       | 2026-01-15 10:35:00 | session_abc
124     | 1        | 2026-01-15 | 11     | 1      | 3       | NULL                | NULL
125     | 1        | 2026-01-15 | 12     | 0      | 2       | NULL                | NULL
```

**Статусы:**
- `status = 0` - Свободен
- `status = 1` - Занят
- `status = 3` - Закрыт

**Резервация:**
- `reserved_until` - До какого времени зарезервирован
- `reserved_by` - Кем зарезервирован (session_id)

**Версионирование:**
- `version` - Увеличивается при каждом изменении

## Преимущества решения

✅ **Просто** - 1 файл JavaScript, без сложных зависимостей  
✅ **Быстро** - внедрение за 5 минут  
✅ **Надежно** - двойная защита (lockForUpdate + версионирование)  
✅ **UX** - таймер, предупреждения, модальное окно  
✅ **Без WebSocket** - не нужен Node.js сервер  
✅ **Без Redis** - работает с обычной MySQL  
✅ **Масштабируемо** - работает на нескольких серверах
